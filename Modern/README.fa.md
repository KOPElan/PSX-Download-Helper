# راهنمای فارسی — PSX Download Helper (نسخه مدرن)

**زبان‌ها:** [فارسی](README.fa.md) | [English](README.md) | [راهنمای فارسی کل پروژه](../README.fa.md)

این نسخه، بازنویسی مستقل برنامه با **.NET 10 و Windows Forms** است. کد نسخه قدیمی مبتنی بر .NET Framework 4.0 در مسیر `PSXDownloadHelper/` نگهداری می‌شود و این نسخه جایگزین یا تخریب‌کننده آن نیست.

## وضعیت فعلی — نسخه ۲.۵.۰

قابلیت‌های پیاده‌سازی‌شده در مسیر مدرن:

- برنامه دسکتاپ Windows Forms با هدف .NET 10
- پراکسی TCP محلی با پردازش ناهمگام
- ارسال درخواست‌های HTTP با قالب absolute-form
- تونل‌سازی HTTPS با متد CONNECT؛ ارتباط TLS بین کلاینت و سرور مقصد رمزنگاری‌شده باقی می‌ماند
- ثبت درخواست‌ها و امکان تنظیم IP و پورت پراکسی
- تنظیم پیش‌فرض امن‌تر: شنود فقط روی `127.0.0.1`
- قوانین بازنویسی میزبان و مسیر CDN با اولویت‌بندی، اعتبارسنجی و ورود/خروجی JSON
- مدیر نشانی‌های آفلاین با نگاشت دقیق URL به نشانی Mirror، اولویت، و امکان تنظیم اختیاری Host و Cookie
- ورود اطلاعات فایل قدیمی `DataHistory.xml`
- واردکردن بخشی از تنظیمات نسخه قدیمی از `app.config` یا XML تنظیمات کاربر
- ابزار کمکی Wi-Fi برای بررسی قابلیت و اجرای فرمان‌های قدیمی Windows Hosted Network

انتقال کامل تمام قابلیت‌ها و تنظیمات نسخه قدیمی هنوز انجام نشده است. مواردی که منتقل نشده‌اند نباید قابلیت تکمیل‌شده تلقی شوند.

## پیش‌نیازها

برای اجرای بسته مستقل:
- Windows 10 یا Windows 11 نسخه x64

برای ساخت از منبع:
- Windows 10/11 x64
- .NET 10 SDK
- Git

بسته self-contained ویندوزی، Runtime موردنیاز .NET را همراه خود دارد؛ اما خروجی اجرای Actions در حال حاضر امضای دیجیتال ندارد.

## ساخت و اجرا از منبع

در PowerShell:

```powershell
dotnet build .\Modern\PSXDownloadHelper.Modern.sln -c Release
dotnet run --project .\Modern\PSXDownloadHelper.Modern\PSXDownloadHelper.Modern.csproj
```

## دریافت بسته آماده ویندوز

1. وارد بخش [Actions مخزن](https://github.com/meicamghe/PSX-Download-Helper/actions/workflows/modern-release.yml) شوید.
2. آخرین اجرای موفق گردش‌کار **Modern .NET release** را باز کنید.
3. از بخش Artifacts، بسته `modern-windows-x64-package` را دریافت کنید.
4. فایل ZIP را استخراج و مقدار SHA-256 آن را با فایل `SHA256SUMS.txt` تطبیق دهید.

برای انتشار GitHub Release نسخه‌دار، tag با الگوی `modern-v*` ساخته می‌شود؛ گردش‌کار پس از موفقیت Build و آزمون‌ها، فایل ZIP و checksum را به Release پیوست می‌کند.

## راه‌اندازی پراکسی

1. برنامه را اجرا کنید و برای آزمایش روی همان رایانه، آدرس پیش‌فرض Loopback را نگه دارید.
2. پراکسی HTTP سیستم یا برنامه کلاینت را روی IP و پورتی که برنامه نمایش می‌دهد تنظیم کنید.
3. برای استفاده از کنسول یا دستگاه دیگر در LAN، آدرس شنود را فقط در صورت نیاز به `0.0.0.0` تغییر دهید.
4. در Windows Firewall فقط روی شبکه Private و مورد اعتماد، دسترسی پورت را محدود و مشخص مجاز کنید.
5. پس از پایان کار پراکسی را متوقف کنید.

**هشدار:** پراکسی را روی اینترنت عمومی یا شبکه ناشناس در دسترس قرار ندهید.

### رفتار HTTPS

برای HTTPS از CONNECT استفاده می‌شود. برنامه مقصد و پورت را برای برقراری تونل می‌بیند، اما محتوای رمزنگاری‌شده TLS را رمزگشایی یا بازرسی نمی‌کند. نصب گواهی ریشه سفارشی یا غیرفعال‌کردن بررسی TLS لازم نیست و توصیه نمی‌شود.

## نگاشت URL به فایل محلی

در اولین اجرا، فایل پیکربندی زیر ساخته می‌شود:

`%LOCALAPPDATA%\PSXDownloadHelper\local-mappings.json`

هر قانون، یک URL دقیق HTTP را به یک فایل موجود روی رایانه نگاشت می‌کند:

```json
[
  {
    "url": "http://example.com/game.pkg",
    "filePath": "C:\\PSXOffline\\game.pkg"
  }
]
```

درخواست GET یا HEAD منطبق، بدون ارتباط با سرور راه‌دور از فایل محلی پاسخ داده می‌شود. برای GET یک محدوده بایت پشتیبانی می‌شود؛ پاسخ معتبر می‌تواند `206 Partial Content` باشد. محدوده نامعتبر یا غیرقابل پاسخ با رفتار تعریف‌شده در پیاده‌سازی مدیریت می‌شود. مسیر فایل باید برای کاربر جاری قابل خواندن باشد.

## قوانین CDN

قوانین CDN روی درخواست‌های HTTP رمزنگاری‌نشده و پس از بررسی نگاشت فایل محلی، پیش از اتصال به سرور مقصد اعمال می‌شوند. درخواست HTTPS به دلیل رمزنگاری TLS قابل بازنویسی نیست؛ برنامه عمداً TLS را رهگیری نمی‌کند.

## نشانی‌های آفلاین

از پنجره اصلی، بخش **Offline URLs** را باز کنید. این بخش ورود و خروجی JSON و واردکردن فایل قدیمی `DataHistory.xml` را پشتیبانی می‌کند.

فایل تنظیمات:

`%LOCALAPPDATA%\PSXDownloadHelper\offline-urls.json`

هر قانون یک URL دقیق HTTP را به URL یک Mirror از نوع HTTP نگاشت می‌کند. تطبیق بر اساس scheme، میزبان، پورت، مسیر و query انجام می‌شود؛ حروف بزرگ و کوچک مسیر در تطبیق مؤثرند. قوانین با اولویت بالاتر زودتر بررسی می‌شوند.

فیلدهای اختیاری `hostHeader` و `cookie` برای سرور Mirrorهایی هستند که به Host یا Cookie خاص نیاز دارند. Cookie فقط در صورت پیکربندی ارسال می‌شود و ممکن است حاوی اطلاعات نشست محرمانه باشد؛ آن را با دیگران به اشتراک نگذارید.

## انتقال تنظیمات نسخه قدیمی

گزینه **Import legacy settings** تنظیمات قابل پشتیبانی را از فایل `app.config` یا XML تنظیمات کاربر وارد می‌کند. آدرس و پورت پراکسی در صورت معتبرنبودن به مقادیر پیش‌فرض Loopback و 8080 برمی‌گردند. زبان، پوسته و برخی گزینه‌های قابلیت‌ها در فایل زیر نگهداری می‌شوند:

`%LOCALAPPDATA%\PSXDownloadHelper\settings.json`

مقادیر Cookie و رمز عبور نقطه دسترسی Wi-Fi منتقل نمی‌شوند. ورود تنظیمات به‌صورت دستی و با انتخاب کاربر انجام می‌شود و فایل XML اصلی را تغییر نمی‌دهد. پیش از شروع پراکسی، آدرس شنود واردشده را بررسی کنید.

## ابزار کمکی Wi-Fi

این ابزار فرمان‌ها و قابلیت قدیمی Windows Hosted Network را بررسی می‌کند. Hosted Network در ویندوز منسوخ شده و ممکن است با نسخه‌های جدید ویندوز یا درایور کارت شبکه سازگار نباشد. این قابلیت معادل Mobile Hotspot جدید ویندوز نیست. پشتیبانی واقعی باید روی سخت‌افزار مقصد بررسی شود.

## آزمون‌های پیش از استفاده عملی

CI ساخت، آزمون‌های یکپارچه‌سازی خودکار و تولید بسته را بررسی می‌کند؛ ولی آزمایش واقعی روی کنسول، کارت شبکه و همه ترکیب‌های Windows 10/11 را انجام نمی‌دهد. پیش از انتشار عملی موارد زیر را بررسی کنید:

1. اجرای اولیه، ساخت تنظیمات و خروج صحیح از برنامه
2. عبور درخواست HTTP و تونل HTTPS با اعتبارسنجی TLS فعال
3. GET/HEAD فایل محلی و محدوده‌های بایت معتبر و نامعتبر
4. ترتیب قوانین CDN و Offline و ورود/خروجی تنظیمات
5. توقف و شروع مجدد پراکسی، قطع کلاینت و timeout سرور مقصد
6. شنود Loopback، اتصال LAN و رفتار Windows Firewall
7. تشخیص پشتیبانی Hosted Network روی کارت‌های شبکه مختلف

## بسته انتشار و صحت فایل

گردش‌کار [Modern .NET release در GitHub Actions](https://github.com/meicamghe/PSX-Download-Helper/actions/workflows/modern-release.yml) پروژه را Build و تست می‌کند و بسته self-contained ویندوز x64 می‌سازد. فایل ZIP همراه با راهنما، مجوز و `SHA256SUMS.txt` در Artifact قرار می‌گیرد.

بسته فعلی **امضای دیجیتال ندارد**. ممکن است Windows SmartScreen هشدار نمایش دهد. SHA-256 فقط برای بررسی یکپارچگی فایل است و هویت ناشر را تأیید نمی‌کند.
